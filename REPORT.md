## Ответы на вопросы

1. **Какую проблему решает файл .gitignore в вашем проекте?**
Файл `.gitignore` исключает из индексации временные файлы, логи, кэш, папки зависимостей и локальные конфигурации с секретами (`.env`), предотвращая засорение репозитория и утечку чувствительных данных.

2. **Почему правило защиты ветки main критически важно для командной работы?**
Оно запрещает прямые коммиты в стабильную ветку, обязывая участников вносить изменения через Pull Request с проведением Code Review и прохождением автотестов CI, что защищает проект от поломок и несогласованного кода.

3. **Что произойдет с кодом, если запустить git revert на коммит с добавлением лицензии?**
Команда `git revert <хеш_коммита>` не удалит старый коммит из истории, а создаст новый коммит, инвертирующий изменения (удалит файл `LICENSE`), сохранив при этом полную и прозрачную историю всех действий в репозитории.
